# マスタデータ

コミックマーケット等、多くのユーザーに共通する大きなイベントの情報を一元管理し、`git pull`を通じて各ユーザーへ配信するための仕組み。各ユーザーのFirestoreは個別（[他ユーザー展開の検討.md](../../01_全体構成/他ユーザー展開の検討.md)参照）のため、自動でリアルタイムに反映されるわけではなく、**「最新のこのリポジトリを取得→反映スクリプトを実行」という一手間で最新化する**方式。

## 収録データ

| ファイル | 対応するテーブル | 内容 |
|---|---|---|
| [イベントマスタ.json](イベントマスタ.json) | イベントマスタ（Firestoreコレクション`event_master`） | コミックマーケット等、共通で使う大きなイベントの情報 |

イベントの日程・詳細等、公開されている情報のみを収録する（[データ取扱いルール.md](../データ取扱いルール.md)のとおり、実データ・個人情報は対象外）。

## 反映方法（各ユーザーが実行）

```bash
cd マスタデータ
npm install
node sync-event-master.js <自分のGCPプロジェクトID>
```

事前に`gcloud auth application-default login`でADCを設定しておくこと（[インストールパッケージ/手順書.md](../../03_リソース構築/インストールパッケージ/手順書.md)ステップ2-4参照）。

**同じイベントIDのレコードは上書き更新される**（提供元が日程・イベント名を修正した場合に追従できる）。**このJSONに載っていないイベントID（自分で個別に追加したイベント等）には一切触れない**ため、自分のデータを壊す心配はない。

## `イベントマスタ.json`の形式

```json
[
  {
    "イベントID": "任意の一意な文字列（例：主催者発行のカタログID等）",
    "イベント名": "イベント名",
    "開催開始日": "2026-12-30",
    "開催終了日": "2026-12-31",
    "ジャンル": null
  }
]
```

`開催終了日`・`ジャンル`は複数日程開催でない場合・不明な場合は`null`でよい（[項目定義書.md](../00_構成について/項目定義書.md)のイベントマスタ定義を参照）。

## 更新の運用（提供元）

1. このフォルダの`イベントマスタ.json`に新しいイベント・修正内容を追記する
2. コミット・push
3. 各ユーザーに更新を知らせる（`git pull`してもらい、上記コマンドを再実行してもらう）
